# Day 4 – Product Requirements Document (PRD)

## Task
Prepare a Product Requirements Document (PRD) for a hypothetical mobile expense tracking app.

## Learning Objectives
- Understand what a PRD is and how it differs from a BRD.
- Learn the structure and components of a standard PRD.
- Understand user stories and how they represent user needs.
- Learn acceptance criteria using the Given-When-Then format.

## Project
Mobile Expense Tracking App

## Key Deliverables
- Full PRD for the expense tracking app.
- 3 user personas.
- 10 user stories with acceptance criteria.
- Features list with P0, P1, and P2 priorities.
- Functional and non-functional requirements.
- Out-of-scope items.
- Success metrics and proposed timeline.
- BRD vs PRD comparison note.

## Main Learning
The task helped me understand that a PRD is more product- and user-focused than a BRD. I also learned how user stories describe user needs and how acceptance criteria define when a feature can be considered complete.
